# 用户指南

## 首次启动

先按[构建与运行](BUILD_AND_RUN.md)编译，然后在仓库根目录运行 [`.\StartQS.cmd`](../StartQS.cmd) 或 [`.\StartConsoleQS.cmd`](../StartConsoleQS.cmd)。这两个启动器默认传入根目录 `data`，并转发额外命令行参数。若要明确指定独立数据目录，可以直接运行程序，例如：

```powershell
.\runtime\TongChuangQS.exe --data '.\demo-data'
```

控制台可将程序替换为 `SocialQS.exe`。程序首次运行会在所选目录生成本地演示数据；保留旧目录可继续查看原有数据。

## 登录与服务

示例数据中 QQ `10001`、`10002` 的演示密码均为 `123456`。请只在本机演示中使用这些合成账号。程序还提供课程模拟的微信、微博、微商服务。账号关联、好友推荐、共同好友、群组申请/邀请/角色以及服务内功能，取决于当前服务能力和演示数据；这些操作都发生在本地项目数据中。

平台会话按服务分别记录。登录一个服务后，若关联关系指向另一个服务，平台可显示待确认登录；用户确认后才切换为已登录状态。服务状态刷新依据数据修订号，两个窗口可共享同一数据目录。

## 聊天演示

运行 [`.\StartChatDemoQS.cmd`](../StartChatDemoQS.cmd) 打开两个 GUI 实例，分别登录 `10001` 与 `10002`，在联系人/会话界面发消息。也可先启动普通 GUI 两次并让它们使用同一个 `--data` 目录。聊天依赖 TCP 节点；默认限于本机回环连接。`--lan` 用于局域网演示时，需自行确保网络环境可达。

发送状态中的 ACK 表示对方进程已保存消息，并不表示对方看过。离线消息保留在发送端待投递，双方节点再次在线时可重试。聊天历史和业务数据均写入所选本地数据目录。

## 数据与故障处理

两个不同账号的窗口可以共享同一个 `data` 目录。若提示账号正由另一个窗口使用，这是同一聊天账号的身份锁；先在另一窗口退出该账号，再重试。若提示服务数据写入锁占用，则是同一服务目录的短时写锁，等待另一窗口完成写入后重试。若目录损坏或部分缺失，先备份并保留现有内容，再使用新的空目录验证；不要为了让启动成功而覆盖旧数据。构建缓存也不会由构建脚本自动清除。

具体能力和安全边界见[架构概览](ARCHITECTURE.md)、[持久化与聊天](PERSISTENCE_AND_CHAT.md)及[测试与限制](TESTING_AND_LIMITS.md)。
